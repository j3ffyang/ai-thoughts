# AGENTS.md 不是人格设定 (Persona)——它是一部用伤疤写成的宪章 (Constitution)

**原文：** [260821-agents-md-not-a-persona.md](260821-agents-md-not-a-persona.md)

![信息图：AGENTS.md 不是人格设定——它是一部用伤疤写成的宪章](../imgs/260821-constitution-scars.png)

问一圈你就会发现，大多数人把智能体 (agent) 的指令文件当成一套戏服。"你是一个高级开发者。""扮演一个大学历史教授。"人格设定提示词 (persona prompts) 有它们的用武之地，但在与一份真正的 `AGENTS.md` 共处数月之后——编辑文档、编写代码、收拾真实的烂摊子——我得出的结论是，人格设定是整个文件中最无趣的部分。真正有价值的内容是另一种东西：运营法则 (operational law)。这些规则不是凭空想象的，而是*挣来的*，每一条都可以追溯到一个具体的事故——某个地方出了错，而且永远不该再犯。

人格设定声称智能体"是什么"。宪章则约束它"能做什么"。前者是一个愿望；后者是判例法 (case law)。这篇文章讲的是后者——通过真实的伤疤来讲述，而且不绑定任何特定工具。无论你的工具读的是 `AGENTS.md`、`CLAUDE.md`、`.cursorrules` 还是 `SOUL.md`，无论你的门控 (gates) 住在 `opencode.jsonc`、`settings.json` 还是某个 MCP 配置里，机制都是一样的：Markdown 塑造智能体如何判断，机器解析的配置门控它被允许做什么。两者无法相互替代，而它们的价值完全取决于其中沉淀了多少教训。

## 锚点事故 (The anchor incident)：一个自己克隆了自己的仓库

8 月 17 日，我让智能体检查两个 GitHub 个人主页是否显示了最新内容，然后说了句"去更新并推送吧。"智能体发现其中一个主页过期了，就在本地找那个仓库的副本——没找到。然后它好心地帮了一个忙：直接在 `git clone` 到我的工作目录树里，于是一个受管仓库现在多了一个嵌套的另一个仓库的克隆。它完成了更新，成功推送，然后把克隆扔在那里，像一个烟头。

我四天才发现。当我终于看到那个目录时，我真的不记得自己创建过它——这种程度的恐惧刚刚好。取证过程 (forensics) 有一个反转：我的 shell 历史记录里什么都没有，因为智能体通过非交互式 shell 执行命令，而这类 shell 永远不会写入 `.bash_history`。但智能体的会话数据库 (session database) 记录了一切：确切的命令、精确到秒的时间戳、甚至触发它的那条我自己的消息。作案者留下了指纹；我只需要知道它们被收在哪个抽屉里。

由此产生的规则现在是指令中最响亮的一行：**永远不要用临时产物污染工作树 (working tree)**——临时克隆应该放在临时目录里，永远不要放进受管仓库，任务结束前必须清除一切残留。而让我夜不能寐的部分是：我运气好，因为这个代码库足够小，一个陌生的目录*看起来*就是陌生的。在一个有成千上万目录的 monorepo 里，一个嵌套仓库会污染 `git status` 的输出——没人再认真看那些输出了——它会破坏每一个向上查找边界的工具的项目根目录检测 (project-root detection)，还会一次会话接一次会话地训练你忽略未跟踪文件警告 (untracked-file warnings)。在大规模仓库里你根本找不到罪魁祸首。预防在那种情况下不是锦上添花——它是唯一有效的机制。

## 伤疤 II (Scar II)：撒谎的文档

我的权限设置 (permission setup) 被描述在两个地方：`AGENTS.md` 中的一段文字和配置文件中的行内注释。在一次编辑中，一句话悄悄溜了进来，声称未匹配的 shell 命令会被"静默拒绝 (silently denied)"。事实恰恰相反——未匹配的命令在宽松默认值 (permissive default) 下会静默*允许*执行。那个错误的句子在文件里待了好几周，声称的是我*希望*拥有的安全姿态 (security posture)，而不是我*实际*拥有的那个。

教训不是"编辑时要小心"。它是结构性的：当两个表面描述同一个事实时，它们会漂移 (drift)，而且漂移的方向一定是危险的方向——朝向更多自信、更少真相。我的修复方案是所有权 (ownership)：一个文件是人类可读的真相，另一个引用它，审查清单 (review checklist) 要求两者保持一致。更好的做法是去重，直到每个事实只有一个家。

## 伤疤 III (Scar III)：提示洪水 (prompt flood)

早期的配置有一个万能兜底规则：所有操作都需要审批。这在大约一天的时间里让我觉得很有责任感。持续不断的提示就是摩擦 (friction)，而摩擦最终会输：我会不假思索地批准那些根本没读过的东西，这比不问还糟糕。万能兜底最终被移除了，取而代之的是默认允许 (allow-driven by design) 的设计——只读操作静默执行，而一份精心挑选的显式破坏性命令清单（`rm`、`git push`、`git reset`）仍然会弹出提示。持久的洞察是：安全剧场 (security theater) 会在压力下被删除，而当它被删掉时，会连真正的保护一起带走。能在日常工作中存活下来的规则，是那些只在真正值得中断时才中断的规则。

## 更多伤疤，简要带过 (Further scars, more briefly)

指令文件是拼接的——它们是一堆 (pile)，不是级联 (cascade)。没有什么覆盖什么；如果全局文件说 X，项目文件说 Y，模型会同时看到两者，然后两个都不听。我是在八条规则几乎逐字存在于两个文件中、然后开始出现措辞分歧时学到这一点的。修复方案是结构性的：每个事实一个所有者，通用规则只放在全局文件中，项目专属规则放在各自的仓库里。漂移从"不太可能"变成了"不可能"。

官方文档说指令文件按"首次匹配生效 (first match wins)"的规则解析。源代码把它们全部拼接在一起。当文档和行为不一致时，行为照常发布，文档事后再道歉——在依赖文档化的保证 (documented guarantee) 之前，先对照源代码或实际系统验证。

符号链接配置 (symlinked config)（真实的文件在 git 仓库中，链接到使用位置）在切换机器时表现优雅——直到某个编辑器用"先写临时文件再重命名 (write-temp-then-rename)"的模式保存，这会静默地把符号链接替换成一份冻结的普通副本。你那份唯一的事实来源 (single source of truth) 仍然存在，完美无瑕但被忽略。基础设施模式 (infrastructure patterns) 失败的方式看起来像是持续成功。这和伤疤 II 是同一个漂移问题——两个事实来源，一个过期了——只是穿上了基础设施的外衣。

`git status` 中显示为已修改的子模块指针 (submodule pointers) 是漂移，不是损坏——而那种通过重置子模块来"清理"的冲动，恰恰会毁掉你选择容忍的本地状态。清洁信号 (hygiene signals) 和错误是不同的物种；一个强迫性地整理状态输出的智能体（或人类），总有一天会毁掉别人的工作。

会话级审批 (session-scoped approvals) 随会话消亡，持久的规则属于版本化配置 (versioned config)。知道哪个旋钮是临时的、哪个是持久的，可以防止两类事故：你以为你有的保护，和你以为你留下的修复。

## 宪章比模型活得更久 (The constitution outlives the model)

每一条存活下来的规则都共享四个特征：它追溯到一个具名事故，它有一个所有者，它是可验证的，而且它足够廉价以至于没人会在压力下删除它。但这些特征只是描述——真正的考验是这些规则*有效*。

克隆那个仓库的智能体很快就会被换掉，换成一个更好的。指令文件和权限配置才是持久存在的部分——用失败写成的制度记忆 (institutional memory)，可被下一个模型读取。这就是为什么"不是人格设定"很重要。人格设定是写给今天的模型看的；宪章是写给它们的继任者看的。记录哪里出了错，写下日期，陈述规则，让你终端的下一个住民继承伤疤，而不是重开伤口。
