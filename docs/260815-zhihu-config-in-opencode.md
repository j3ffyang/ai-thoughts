# zhihu skill + CLI — install and configuration in OpenCode

This note records how the `zhihu` skill (v0.3.0) and its official CLI were installed and configured in OpenCode on this machine, including the headless-environment auth detour. Facts below were verified by running the actual commands on 2026-08-15, not from memory.

## What the skill is

The `zhihu` skill exposes the Zhihu open platform through an official CLI (`zhihu-cli`). In OpenCode it lives at `.opencode/skills/zhihu/` and is auto-discovered at session start. Daily tasks go through the CLI — `search zhihu` (community answers), `search global` (external web), `hot` (trending), `answer` (Q&A), and `me ...` (the current user's own content) — while the raw HTTP API, OAuth and MCP docs are only read for development integration.

## Installing the CLI

The skill package ships no binary. After the user approved, `scripts/setup.sh` read the official manifest, downloaded `zhihu-cli 0.3.0` for `linux-amd64`, and verified the host, file size, SHA-256, archive structure and the binary's self-reported version before installing it to `~/.local/share/zhihu-cli/current/zhihu-cli` (the XDG user data dir). No sudo, no PATH modification. A follow-up status check reported `installed: true` and `compatible: true` (min required 0.1.0, no update available).

## Authentication in a headless environment

The Access Secret is generated by the user at https://developer.zhihu.com/profile. `auth set --secret-stdin` normally writes the credential to the operating system keychain — on Linux, Secret Service/D-Bus (e.g. GNOME Keyring). This machine has no session D-Bus, so the first attempt returned `KEYCHAIN_UNAVAILABLE`; the CLI deliberately never degrades the credential to a plain file.

Per the CLI docs, the fallback for SSH/CI/container-style environments is a process-level `ZHIHU_ACCESS_SECRET` environment variable injected by the host (in this case opencode). Business commands read the env var first and the keychain second, and never silently fall back when the env var is set but invalid. `auth status` confirmed the switch: `source: environment`, masked `f8af...657d`, `keychain: unavailable`.

## Verification

Initialization was verified with two online calls (both consume API quota):

- `auth status --verify` → `verification: valid` (one personal-content request).
- `me contents --type all --limit 1` → `Code 0, success`, empty item list — an empty list counts as a pass.

The skill is now ready for searches, hot list, answer, and reading the user's own content.

Raw HTTP API smoke test:

```bash
curl -G 'https://developer.zhihu.com/api/v1/content/zhihu_search' --data-urlencode 'Query=怎么理解opensource文 化'   -H "Authorization: Bearer $ZHIHU_ACCESS_SECRET" -H "X-Request-Timestamp: $(date +%s)" -H 'Content-Type: application/json'
```

## Security notes

The Access Secret is only ever passed through stdin (`auth set --secret-stdin`) or the `ZHIHU_ACCESS_SECRET` env var, never echoed in replies, never written into the skill directory, the project, or a `.env` file, and never committed. The `.opencode/skills/zhihu/` directory is currently untracked in git; committing it is still pending.
